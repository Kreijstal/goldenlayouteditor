# Additional archive and compression readers

The lazy archive panel handles `.7z`, `.ar`, `.cpio`, `.cab`, `.rar`, `.cbr`, `.cb7`, `.cbt`, `.xar`, `.zipx`, `.bz2`, `.bzip2`, `.xz`, `.lzma`, `.lha`, `.lzh`, `.rpm`, `.srpm`, `.deb`, `.udeb`, `.tbz`, `.tbz2`, `.txz`, `.tar.bz2`, `.tar.xz`, `.gzip`, `.aab`, `.mcpack`, `.mctemplate`, and `.mcworld`.

It lists paths, sizes and entry types, searches entries, extracts a selected regular file, previews bounded text/hex samples, downloads the complete selected file, and opens an extracted in-memory file using the editor's viewer routing. Links/directories are listed without following them. Imported files are read-only transient memory files; importing does not write to the server workspace. Empty packages can legitimately have zero payload entries.

Pinned `libarchive.js 2.0.2` supplies the local libarchive WASM/module worker. We call its flat native entry-list API, avoiding its object-tree helper (which treats archive path components as object keys). We provide Comlink error/cancellation/time limits. Standalone compressed streams use explicit format selection: seek-bzip 2.0.0, xz-decompress 0.2.3, lzma 2.3.2 and browser gzip decompression. They appear as one decompressed file. Compressed tar continues through libarchive. XAR has a separate bounded SAX/zlib reader because this libarchive build did not decode its TOC. XAR supports plain/zlib payloads; its checksums are not verified.

All assets are local and generated by `npm run build:archive`, included in `npm run build`. No archive chunk, codec, worker or WASM loads at startup. Closing terminates pending workers. Input limit: 128 MiB. Selected/expanded file limit: 64 MiB. Entry-list limit: 10,000. Operation timeout: 60 seconds. Some decoders allocate their output before the expanded-size check; workers isolate that work and can be terminated. XAR TOCs have an 8 MiB declared limit and bounded nesting.

Only encryption-free single-volume archives are supported by this panel; password prompts and multi-volume joins are not implemented. Compression methods and variants are limited to the pinned readers. A ZIPX suffix does not guarantee that every ZIPX compression/encryption method is available. APK/AAB/Minecraft packages are inspected as ZIP containers, not executed. RPM is inspected as a payload container, not installed. The supported alias `.hdf` in the separate scientific panel is HDF5 only.

`npm run test:archive-reader` tests listing, extraction, content, escaping, search, nested-viewer handoff, worker disposal, local requests and lazy startup for all 30 suffixes. It generates its own small fixtures, including a nonempty RPM; small RAR/CAB/LHA regression fixtures retain libarchive attribution. Optional `TEST_7Z_PATH`, `TEST_RAR_PATH`, `TEST_CAB_PATH`, `TEST_LZH_PATH`, `TEST_XAR_PATH`, and `TEST_RPM_PATH` can add external fixtures.

Licenses are retained in `public/licenses/imported-viewers/`: libarchivejs MIT, libarchive BSD notices, Comlink Apache-2.0, seek-bzip MIT, LZMA MIT and XZ-decompress MIT/public-domain dependency notices. Runtime sources are unmodified; the host adapters and XAR reader are repository code.
